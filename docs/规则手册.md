# 规则手册（用户视角）

这份文档把工具的全部判断规则用大白话讲一遍，给**非程序员**看。
开发视角的 RULES.md 信息一致但更技术，需要查代码位置时去那看。

---

## 1. 工具一句话

> 你给每只股票打一个**意图标签**，工具按这个意图在期权链里选合约、排序、
> 在你已开仓后给提醒。**不会自动下单**——所有建议都是文字，最终要不要点
> "Open" 是你的事。

---

## 2. 意图（Intent）—— 最核心的概念

每只你跟踪的股票必须打一个意图标签。意图决定工具**要不要扫**这只票、
**用什么口径扫**。

| 标签 | 适合谁 | 工具会卖什么 | 风格 |
|---|---|---|---|
| `CORE_HOLD` | 我打死不卖、长期裸持 | 不卖 | 工具完全不碰它 |
| `INCOME` | 我手里有底仓，想收 premium 当租金 | 卖看涨期权 (CC) | 保守：远 OTM、月权 |
| `TRADE` | 我想做短线波段 CC | 卖看涨期权 (CC) | 激进：近月、Δ 略高 |
| `WANT_TO_OWN` | 这票我想低价接，没接到也吃 premium | 卖看跌期权 (CSP) | strike 不超过我设的目标价 |
| `WATCH` | 只想看价格 + 财报，不卖期权 | 不卖 | 工具只做价格跟踪 |

**特殊修饰符 — Wheel ↻**：勾上后，CSP 被接应（要买股票）→ 自动翻成
`INCOME`；CC 被行权（股票被买走）→ 自动翻成 `WANT_TO_OWN`。这就是经典的
"轮转策略"自动化。

---

## 3. 工具怎么帮我选开仓合约

### 3.1 不同意图用不同口径

| 意图 | 看哪种期权 | Δ 范围 | 距到期天数 | 怎么排序 |
|---|---|---|---|---|
| `INCOME` | 看涨 (CALL) | ≤ 0.20 | 25–55 天 | 年化收益率高的在前 |
| `TRADE` | 看涨 (CALL) | 0.25–0.35 | 7–21 天 | 绝对 premium 高的在前 |
| `WANT_TO_OWN` | 看跌 (PUT) | ≤ 0.30 | 25–55 天 | 年化收益率高的在前 |

> Δ（Delta）可以理解为"被行权的概率"，0.20 就是大约 20% 概率。
> 数字越小越保守。

### 3.2 全局硬规则（写死在代码里，不可关）

| 规则 | 为什么 |
|---|---|
| **跨财报的合约一律不要** | 财报前期权 IV 高看似诱人，但等于赌财报方向，不在工具立场内 |
| **默认只看月权（每月第三个周五）** | 周权流动性差。只有 SPY/NVDA 这种大票才适合周权（per-symbol 单独勾"允许周期权"） |
| **没买卖盘报价的合约不要** | 没人挂单的合约，你点了也成交不了 |
| **`WANT_TO_OWN` 没设目标价 → 整只票被跳过** | 配置不全宁愿不出建议，也不要烂 CSP |

### 3.3 年化收益率怎么算

```
卖 CC 的年化收益率 = (单股 premium / 当前股价) × (365 / 距到期天数)
卖 CSP 的年化收益率 = (单股 premium / 行权价) × (365 / 距到期天数)
```

CC 用现价（占用的是股票本身），CSP 用 strike（保证金按 strike 冻结）。
本质都是"每股拿到多少 premium / 每股锁了多少钱"。

## 4. 已开仓的提醒规则

对你**已经卖出去、还没到期**的每张期权，工具会给一个建议标签。优先级
从上往下匹配，**第一个匹配的就停**——不会同时给两条建议。

| 优先级 | 触发条件 | 建议 | 颜色 |
|---|---|---|---|
| 1 | 财报落在到期日之前 / 距到期 ≤ 7 天 | `ROLL`（滚到下个周期） | 琥珀 |
| 2 | premium 已衰减 ≥ 80% | `CLOSE`（关仓锁利） | 翠绿 |
| 3 | 当前 mark ≥ 2 倍开仓 premium | `STOP_LOSS`（止损） | 橙 |
| 4 | \|Δ\| ≥ 0.50（深度 in-the-money） | `ROLL`（紧急滚） | 玫红 |
| 5 | premium 衰减 ≥ 50% **且** 距到期 ≤ 7 天 | `CLOSE` | 翠绿 |
| 6 | \|Δ\| ≥ 0.40 **且** 距到期 ≤ 7 天 | `ROLL` | 琥珀 |
| 7 | 都不满足 | `HOLD`（继续拿着） | 灰 |

### 设计要点

- **`STOP_LOSS` 排在 `ROLL` 前面**：mark 翻倍说明亏损已超出该单的风险预算，
  这时再 roll 出去收个小 credit 是搬椅子不是修船。给独立标签因为产品
  语义是"你在亏，自己决定"，不是"漂亮锁利"。
- **50% 利润和 0.40 Delta 都加了"距到期 ≤ 7 天"闸门**：长 DTE 的 50%
  利润不急着关、长 DTE 的中等 Δ 也还没到必须动手——再等等让 theta 吃。
- **永远不会自动下单**：所有建议都是文字。决定权在你。

## 5. Telegram 提醒规则

如果你配了 Telegram，工具会在以下时机自动推送：

### 5.1 持仓告警

| 类型 | 触发 | 安静时段会推吗 |
|---|---|---|
| 已赚 50% premium | premium 衰减 ≥ 50% | 不推 |
| 已赚 80% premium | premium 衰减 ≥ 80% | 不推 |
| Δ 警戒 | \|Δ\| ≥ 0.40 | 不推 |
| Δ 危险 | \|Δ\| ≥ 0.50 | **会推**（critical 级别例外） |
| 止损 | mark ≥ 2 倍开仓 premium | 不推 |
| 财报冲突 | 财报落在到期前或距到期 ≤ 7 天 | 不推 |

### 5.2 机会提醒

| 类型 | 触发 |
|---|---|
| 高年化机会 | 任意意图的排名第一候选年化收益率 ≥ 40% |

### 5.3 推送行为

| 规则 | 行为 |
|---|---|
| **安静时段** | 22:00–07:00（本地时间）不推 Telegram，但事件还是写库；critical 级别例外 |
| **去重** | 同一个合约的同类告警 6 小时内不重复推 |
| **配错或没配** | 没填 token 就 graceful 降级，控制台打个 warning，不会崩 |

### 5.4 Δ 告警自动附 roll 建议

工具发 Δ 警戒 / Δ 危险时，会**自动**算 roll，把最佳候选拼到消息后面：

```
🔴 NVDA P140 2026-05-04 Delta=0.55 触发 critical (0.50)
  → roll: P135 2026-06-01 (DTE 42, Δ 0.20, net +0.20)
```

只对 Delta 类附加。利润 / 财报 / 止损 这三类的合理动作不是 roll，附了
反而误导。

## 6. Roll 模拟规则

只在两个时机算 roll：

1. 你点开一个有 ROLL 建议的持仓 → 详情页展开候选表
2. Telegram 发 Δ 告警 → 消息末尾附 top-1

### 6.1 候选过滤

| 规则 | 为什么 |
|---|---|
| 新到期日 > 现有到期日 | "Roll" 必须延期，不能换近的 |
| 新合约方向 = 现有方向 | P→P / C→C，不翻向 |
| CC：新 strike ≥ 现有 strike | 向上滚或平移，不向下 |
| CSP：新 strike ≤ 现有 strike | 向下滚或平移，不向上 |
| 新 \|Δ\| < 0.40 | 别 roll 完立刻又触发警戒 |
| 新合约有买卖盘报价 | 没人挂单等于不能开 |
| 7 ≤ 新距到期天数 ≤ 60 | 太短没意义，太长不如直接开新仓 |

### 6.2 净 credit 怎么估（保守）

```
关仓成本  = 现有合约的 ask（最高要价）
开仓收入  = 新合约的 bid（最低买价）
净 credit = 开仓收入 - 关仓成本
```

**净 credit 可以是负数**——工具只报 chain 允许什么，要不要做 net debit
roll 是你的事。

排序：按净 credit 降序，取前 5。

## 7. Wheel（轮转）自动翻转规则

每次同步持仓后，工具对比前后两次快照，**两个信号必须同时满足**才算被
assignment：

```
信号 A：某张 short 期权前一次还在，这次没了
信号 B：同账户、同股票的股数变化方向匹配
        - CSP（卖看跌）被接 → 股数 +100×合约数
        - CC（卖看涨）被行权 → 股数 -100×合约数
```

| 触发 | 翻成的意图 |
|---|---|
| CSP 被接（要买股票了） | `INCOME`（手里有股票了，开始收 CC 租金） |
| CC 被行权（股票被买走） | `WANT_TO_OWN`（恢复 CSP 模式等接回） |

### 边界情况

- 单边信号都不算（只有期权消失但股数没动 = 自己 BTC 关仓 / 过期作废 / 滚动）
- 只对勾了 Wheel 的 symbol 翻
- 跨账户隔离：A 账户的 assignment 不被 B 账户的股数变化干扰

> 为什么不直接查 IBKR 的成交记录？因为 IBKR 的 API 只返回**当天**的 fill，
> assignment 经常晚一天才出现。对比持仓快照更可靠。

## 8. 工具会做什么 / 不会做什么（项目立场）

| 类别 | 立场 |
|---|---|
| 自动下单 | ❌ **永远不会**。所有建议都是文字 |
| 赌财报 | ❌ 跨财报的合约硬规则排除 |
| PMCC / collar / hedge | ❌ 暂不支持，可能永远不做 |
| 抓 Yahoo / 网页爬虫 | ❌ Finnhub 一家就够 |
| 自动 backtest | ❌ 等"建议反馈环"攒够数据再说 |
| 自动调 Δ / DTE 阈值 | ❌ 你觉得不合适就改 yaml 配置 |

## 9. 阈值怎么改

| 想改的东西 | 在哪改 |
|---|---|
| Δ 警戒 / 危险 / 止损倍数 | `config/alerts.yaml` |
| 安静时段 / 去重窗口 | `config/alerts.yaml` |
| Telegram 推送年化收益率阈值 | `config/alerts.yaml`（默认 40%） |
| 各意图的 Δ / DTE / 排序口径 | `config/intents.yaml` |
| 某只 symbol 的意图 / 目标价 / Wheel | Web 面板里左侧点 symbol → 编辑（最方便） |
| 后台任务频率 | `.env` 里 `OPTIONS_TOOL_*_INTERVAL_MINUTES` |

改完 yaml 要**重启工具**才生效（重新跑 `bash scripts/run.sh`）。
Web 面板里改的（symbol intent / 目标价等）即时生效不用重启。

## 10. 默认阈值速查

```yaml
# 告警相关（config/alerts.yaml）
quiet_hours_start: "22:00"   # 安静时段开始
quiet_hours_end:   "07:00"   # 安静时段结束
dedup_window_hours: 6        # 去重窗口

profit_take_50: true         # 50% 利润推送
profit_take_80: true         # 80% 利润推送
delta_warning: 0.40          # Δ 警戒
delta_critical: 0.50         # Δ 危险
stop_loss_multiplier: 2.0    # 止损倍数
earnings_conflict_dte: 7     # 财报冲突天数
roc_threshold_annual: 0.40   # 推送年化收益率阈值
```

```yaml
# 各意图过滤（config/intents.yaml 摘要）
INCOME:      Δ ≤ 0.20    DTE 25-55   排序 = 年化 ROC
TRADE:       Δ 0.25-0.35 DTE 7-21    排序 = 绝对 premium
WANT_TO_OWN: Δ ≤ 0.30    DTE 25-55   排序 = 年化 ROC
```

调度：

| 任务 | 频率 |
|---|---|
| 拉 chain 到缓存（让点击秒开） | 每 5 分钟 |
| 跑全部告警 detector | 每 10 分钟 |
| 增量更新 IV 历史 | 工作日 22:00 UTC |
| 拉当天 fills | 工作日 21:00 UTC |
